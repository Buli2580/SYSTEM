Run `node scripts/world-foundation/benchmark.cjs recorded.jsonl summary.json` from the repository. Input is UTF-8 JSONL, one record per line. The tool fails closed on missing frames, invalid bounds, metadata, negative timings, and mixed/out-of-order timestamps. Output contains nearest-rank p50/p95/p99, arithmetic mean/max/count, aggregate FPS = 1000 / mean frameMs, timestamp bounds and preserved metadata. It does not manufacture missing CPU/GPU values; absent metrics are null and partial metrics retain their measured sample count. FPS uses recorded frame duration rather than wall-clock spacing; include every rendered frame and disclose dropped samples in conditions.

This is a schema example, not measured evidence; replace SHA and metadata with actual values. Platforms are `android-physical`, `android-emulator`, `desktop`. Presets LOW/MEDIUM/HIGH. Scenario IDs and minimum wall durations: `idle5min` 300 seconds, `tps10min` 600 seconds, `continuous15min` 900 seconds, `enterexit10` ten entry AND exit events, `restart` at least one restart-restored event. Duration alone does not certify correct interactions; retain observation notes alongside recordings.

Frame record fields: `type:"frame"`, `timestamp` canonical UTC `YYYY-MM-DDTHH:mm:ss.fffZ`, `frameMs` positive finite milliseconds. All timestamps, including start/end/events, require exactly three fractional digits and valid calendar dates; timezone offsets and Date.parse rollovers are rejected. Optional finite nonnegative fields: `cpuMainMs`, `cpuRenderMs`, `gpuMs`, `pssMb`, `temperatureC`, `batteryPercent` (0..100). Omit or use null for unavailable metrics. Sample timings must come from their named subsystem; never substitute frameMs for CPU/GPU time. PSS is Android process proportional-set memory, not Unity heap; obtain device telemetry separately if unavailable in Unity. Temperature must describe its source/units in conditions. RAM summary max is sampled peak, not guaranteed process lifetime peak.

Optional ordered events: `{"type":"event","timestamp":"...Z","name":"world-enter","durationMs":123}`. Names: world-enter (RN request to first usable Unity frame), world-exit (back request to responsive RN), restart-restored (verified snapshot revision/save preservation after process restart), crash, anr. Duration optional. End record: `{"type":"end","endedAt":"...Z"}`. End is mandatory; interrupted recordings need explicit review and must not be called completed scenarios. Zero observed crash/ANR events means no reported event, not independently proven absence: collect logcat/Android vitals evidence separately. APK/AAB bytes should be recorded from the exact built artifact alongside summary (not inferred from project size).

`compare(a,b)` in benchmark.cjs rejects different platform/device/OS/preset/scenario/conditions. Compare release builds with matching resolution, warmup, instrumentation and thermal conditions. SHA may differ to compare builds. Keep raw recordings and summaries together; redact personal data, GPS and tokens.

Execute five scenario recordings for each selected preset. TPS includes camera rotation, movement, portal interaction; entry/exit includes background/foreground, back and lock/unlock observations. Restart must verify RN-owned profile/revision persistence and absence of duplicate progression. Record startup/return durations and failures as events. Start from thermally stable device; record charging/battery conditions and repeated trials. Do not uninstall the existing RC3 to test. No connected physical run was performed by this tooling task.

The analyzer never certifies scenario completion: `scenarioComplete` was removed. `structuralCriteriaMet` requires minimum scenario duration AND `frameCoverageRatio = sum(frameMs)/(endedAt-startedAt)` in the inclusive range 0.95..1.05. The 5% tolerance allows capture boundary/timing overhead; missing/doubled frame durations beyond this limit fail structural checks. Zero wall time fails coverage. Coverage is only an arithmetic consistency check; it cannot prove honest timestamps, movement or correct actions. For entry/exit, require at least ten ordered alternating enter/exit pairs with a numeric nonnegative durationMs on every event and no unmatched entry/exit. Restart requires a restart-restored event with a measured durationMs. `scenarioVerified` is always false: attach separate manual/runtime evidence for interactions, lifecycle, preserved RN revision/save and absence of duplicate progression; the analyzer does not infer that evidence from a recorder event name. Crash and ANR events are independent observations, not proof of scenario correctness.
